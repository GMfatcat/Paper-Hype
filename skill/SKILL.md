# Dissecting Paper Hype（論文營銷號實驗）

## Overview
受控實驗:把**真實論文**改寫成「營銷號」吹捧版,再逐篇拆解其話術。目的是**媒體識讀/防騙**——讓使用者學會在 Threads 等動態裡分辨「純吹捧 vs 真有料」,不是真的要產出可發布的行銷文。

**倫理框架(必守)**:論文必須真實存在(正確標題 + arXiv/DOI);每篇都附誠實的「真實版」對照(含限制);**每個產出檔開頭都嵌入固定警語**(見模板 A),讓任何單篇被單獨複製出去時仍帶著「受控示範、非真實評價」的標記——這是結構性防呆,不能只靠意圖判斷。若使用者要的是真要拿去投放的宣傳文,這個 skill 不適用——婉拒。

## 兩種模式（先判斷走哪條）
- **MODE A 實驗模式**(論文 → 營銷號 → 拆解):使用者給「領域/筆記」要研究吹捧手段。走下方〈MODE A〉全段。
- **MODE B 快篩模式**(貼文 → 0–100 營銷號分數):使用者**貼一則貼文(URL 或內文)問「這是不是營銷號 / 給個分數」**。跳到〈MODE B:快篩模式〉。
- 倫理硬關卡兩模式都適用:都不產出可發布行銷文;Mode B 只做「判讀」不做「改寫推廣」。

# ═══════ MODE A:實驗模式（論文→營銷號→拆解） ═══════

## When to Use / NOT
- **用**:使用者想了解營銷號吹捧論文的手段/高頻關鍵詞/句式;給定領域(或指向自己的研究筆記)要「標題+內文吹捧 + 分析」。
- **不用**:要你寫一篇真的拿去發的行銷貼文。

## Confirm First（開工前用 AskUserQuestion 問清,有預設就直接走預設並說明）
0. **倫理硬關卡**:若偵測到使用者意圖是「產出可直接發布的行銷/宣傳內容」(訊號:「發 IG/Threads」「可直接 po」「幫我宣傳這個產品」),**停止並說明本 skill 僅供媒體識讀,不產出可發布行銷文**。確認是識讀/研究用途才繼續。
1. **論文來源**:讀使用者既有筆記挑論文 vs WebSearch 全新找。預設:先 Glob/Read 掃工作目錄找筆記(「筆記」= 內含論文標題/arXiv 連結的 `.md`/`.txt`)。
2. **領域↔檔案對應**:盤點後**先列出「領域 → 對應檔案」候選清單給使用者確認**(一檔多領域就拆、一領域多檔就合、檔名與領域無關就靠內容判定),確認後才開工。沒有筆記才改 WebSearch。
3. **領域清單 + 每領域篇數**(預設每領域 3 篇)。
4. **輸出語言**(預設繁體中文;若選英文,記得同步把模板 A 的語言指示改掉)、**輸出資料夾**(預設工作目錄下新建 `營銷號實驗/`)。

**檔名規則**:`NN_領域代號.md`,NN 依領域清單順序兩位數編號(`01`、`02`…),領域代號用簡短英文或縮寫(如 `01_KAN.md`、`05_TDL.md`),避免中文檔名以降低 Cygwin/路徑問題。

## Pipeline
1. **盤點來源** — Read/Glob 掃目錄;依「Confirm First 第 2 點」列出領域↔檔案候選給使用者確認。領域歸類順序:① 子資料夾名 → ② 檔案 H1 標題 → ③ 檔名關鍵字 → 都不行就請使用者指認。
2. **建輸出資料夾** — 直接用 Write 寫出第一個產出檔(或先寫 `00_營銷號分析報告.md` 佔位),父目錄會自動建立;不需要、也不要用 Bash `mkdir`(中文路徑雷)。
3. **每領域並行派一個 subagent**(`model: sonnet`,一次最多約 10 個並行,超過就分批),讓它:讀對應筆記(或 WebSearch)→ 挑真實論文 → 產出對照 → **直接 Write 到指定的唯一編號檔名**(如 `01_KAN.md`)→ **只回傳一行確認 + 選用論文標題**。Prompt 用 `references/templates.md` 的模板 A。一個領域對應多個筆記檔時,把多個路徑都列進模板的 `{筆記路徑}`。
4. **驗證 + 清理** — 先在心裡列出「預期檔名清單」(`01_…`~`NN_…` + `00_…`),用 Glob 撈出資料夾實際檔案,**兩者比對**:預期有但缺 → 重派;實際多出的(`.bak`、改錯名、重複)→ 即「命名跑掉」,清掉。清檔用 Bash `rm`(英文路徑下安全;路徑含中文則請使用者手動刪,別硬跑 bash 迴圈)。**抽查幾個 arXiv 編號是否真實**(守倫理底線)。缺的最多重派 2 次,仍失敗就告知使用者該領域略過。
5. **逐篇評分** — 主代理讀全部產出檔,用下方 6 維度評分,做總表。**每篇至少替總分附一句理由或一句照抄原文的證據**(識讀報告要可追溯)。檔多時分批讀,別一次塞爆 context。
6. **寫分析報告** `00_營銷號分析報告.md`(模板 C):評分總表、高頻關鍵詞、句式模板、手段 taxonomy、防騙清單。

## Scoring Rubric（每維 0–10,越高=越營銷/越誤導,總分 60）
| 代號 | 維度 | 看什麼 |
|---|---|---|
| A | 標題聳動度 | 震驚體/戰鬥詞/末日詞密度 |
| B | 誇大失真度 | 吹捧與真實貢獻的落差 |
| C | 隱瞞限制度 | 對真實限制(只在玩具任務/需專用硬體/精度損失/未臨床驗證)隱瞞或一句帶過 |
| D | 外行誤導度 | 不熟領域者會產生多嚴重的錯誤認知 |
| E | 情緒操弄度 | FOMO/職業焦慮/恐懼/對立的強度 |
| F | 假證據度 | 匿名「大佬/實驗室/網友」、捏造引言/內部情報、模糊數據 |

## 報告必含的洞察（不要只堆標題,要講「為什麼誤導」的機制）
- 哪領域營銷指數最高、最害外行誤會、為什麼。
- 高頻關鍵詞分類:震驚體/戰鬥暴力詞/造神武器詞/末日取代詞/宏大敘事/假社會證明/排他裹挾/數字模糊化/反轉打假。
- 高頻句式:「這意味著什麼?意味著…」「你打算何時進化?」「據可靠消息…」「收藏,X 年後感謝自己」。
- Threads 防騙快速清單 + 正面訊號清單。
- **跨篇通則**:吹捧是模板驅動、跟論文份量無關;benchmark/立場文/打臉論文都能照吹;「真數字+抽掉前提」最難識破;反向營銷(打假)也是流量生意。

## Operational Gotchas（踩過的雷,務必遵守）
- **別用 Bash 跑 PowerShell cmdlet**(Get-ChildItem 等)——常被 deny rule 擋住並中斷整批並行。用 Read/Glob/Grep。
- **中文路徑會讓 Cygwin bash 偶發崩潰**(生成 `bash.exe.stackdump`,連 `echo` 都回空白)。在中文目錄優先用 Read/Glob/Edit/Write,少用 bash 連發迴圈。
- **subagent 必須「直接 Write 到指定絕對路徑 + 唯一編號檔名」**,prompt 要強調檔名,否則檔名跑掉或互相覆蓋。
- **subagent 只回傳一行**,不要回傳整篇全文(否則主代理 context 爆)。
- **派完務必逐檔驗證存在性**再評分,別假設都成功。

## Common Mistakes
- 用假論文/錯 arXiv → 失去對照價值。務必真實。
- 真實版沒老實列限制 → 對照組失效、評分失準。
- 報告只堆聳動標題,沒拆「為什麼會誤導外行」的機制 → 達不到識讀目的。
- 把營銷號版當真實評價輸出 → 必須全程標明是受控示範。

# ═══════ MODE B:快篩模式（貼文→0–100 營銷號分數） ═══════

## 何時走這條
使用者**貼一則真實貼文**(Threads/X 的 URL 或直接貼內文)問「這是不是營銷號 / 幫我看這篇 / 給個分數」。產出:一個 **0–100 營銷號分數**(越高越該懷疑)+ 燈號 + 各維度拆解 + 查證落差 + 一句結論。

## Confirm First（有預設就直接走並說明）
0. **倫理關卡**:這是「判讀真實貼文」用途,正常放行;若使用者其實要你「幫他把這篇改得更吸睛 / 寫類似的爆款」→ 停止(那是產行銷文)。
1. **輸出**:預設**直接在對話回覆判決**;若使用者要存檔,寫到工作目錄 `hype_check/貼文判決_<簡短標籤>.md`(ASCII 資料夾)。
2. **取文方式**見下。取不到就請使用者貼上內文,**絕不憑記憶或猜測貼文內容**。

## 取文 Adapter（可替換接縫;後續 pipeline 不依賴取文怎麼來）
取文方式由穩到強,**取到就進「拆解」,取不到就請使用者貼上,絕不憑記憶杜撰貼文**:
- **方式一 使用者貼上**(永遠可用的保底):直接貼內文 → 進拆解。
- **方式二 Docker/Scrapling 容器**(已實作,推薦給 Threads/X URL):
  - 工具在 `scrapling-fetcher/`(Dockerfile + fetch.py + README)。一次性建置:
    `docker build -t hype-fetcher ./scrapling-fetcher`（在本 skill 目錄下執行;或換成你的 skill 安裝路徑）
  - 取文:`docker run --rm hype-fetcher "<貼文URL>"` → stdout 一個 JSON。
  - 用 JSON 的 **`post_text`(og:description 等的最佳猜測)+ `text_excerpt`(跑 JS 後的完整可見文字)**當貼文內文;`text_excerpt` 常含正文但夾雜導覽列/「Related threads」雜訊,拆解時挑出真正的貼文段落即可。
  - `ok:false` 或內容明顯殘缺 → **改請使用者貼上**,不要對殘缺內容硬評分。
  - **實測(2026-06)**:`StealthyFetcher`(camoufox 跑 JS)成功抓到**真實公開 Threads 貼文完整正文**;arXiv 等一般頁面也 OK。**X(Twitter)登入牆較重,未登入常只剩殘缺 og**,此時走貼上。
- **方式三 WebFetch**(輕量,僅備援):X/Threads 多為 JS 動態 + 反爬,WebFetch 常失敗或只拿到殘缺;能用方式二就別用它抓社群貼文。

## Pipeline
1. **取文** — 依上方 adapter 拿到貼文純文字。
2. **拆解**(主代理)— 從貼文抽出三類:
   - **可查證引用**:arXiv ID / DOI、GitHub repo、論文標題、產品或模型名。
   - **量化/比較宣稱**:「暴增 X%」「打敗 Sora/GPT-4o/ECMWF」「N 顆神經元」等。
   - **話術訊號**:對照〈手段 taxonomy〉與〈防騙清單〉(可參考本 repo 的 `examples/cross-batch-playbook.md` 作知識庫)。
3. **深度查證**(每個可查證引用**並行派一個 subagent**,`model: sonnet`,用模板 D)— 開連結 → 確認真實存在 → 讀 abstract/README → 結構化回報:① 來源是否真實 ② **原文真實宣稱 vs 貼文宣稱的落差** ③ **原文有寫、但貼文漏掉/淡化的限制**。
   - **沒有任何可查證引用** → 不需派查證,但維度 G 直接拉高(空口無憑)。
   - **連結查不到/開不了** → 標「**不可查證**」,**不是「造假」也不是「真實」**;維度 G 加分,B/D 以「無法核對」記。
4. **評分**(主代理)— 用下方 7 維 rubric 結合查證結果算 0–100,**每一維附一句證據(照抄貼文句子 或 查證結論)**。
5. **判決報告** — 用模板 E 輸出:總分 + 燈號 + 維度表 + 查證落差表 + 一句結論。

## Mode B 評分 Rubric（0–100,越高越可疑）
| 代號 | 維度 | 配分 | 看什麼 |
|---|---|---|---|
| A | 標題/開場聳動 | 15 | 震驚/碾壓/封神/末日詞;宣判某技術死亡 |
| B | **宣稱 vs 原文落差** | 15 | 靠查證:貼文宣稱遠超論文實際做的(偷換概念/以偏概全) |
| C | 數字抽前提·比較錯位 | 15 | 暴增X%沒講從多少到多少、換對手、拿AI比疲勞人類 |
| D | **隱瞞限制** | 15 | 靠查證:原文有寫限制但貼文不提/一句帶過 |
| E | 情緒操弄 | 15 | 失業倒計時/健康焦慮/民族/FOMO/陰謀論/收藏轉發 CTA |
| F | 假權威·假社會證明 | 15 | 匿名「圈內瘋傳」、點名大佬卻無連結、無來源統計 |
| G | 來源不可查證 | 10 | 沒附論文/repo,或附了但與宣稱對不上/查不到 |

**燈號**:0–25 🟢值得讀 / 26–50 🟡自己查證再信 / 51–75 🟠高度存疑 / 76–100 🔴典型營銷號,可滑掉。

> **B 與 D 是 Mode B 的靈魂**:它們靠真的去查原文,這是純關鍵詞掃描做不到、也是 baseline 憑記憶會做錯的地方。

## Mode B 紀律（從基準測試學到的硬規則,務必遵守）
- **絕不憑訓練記憶斷言論文/repo 事實**——必須實際 WebFetch 查證。記憶只能當「待查證的假設」,不能當證據寫進報告。(基準測試中 subagent 零工具呼叫、憑記憶把 GraphCast 講成「發表於 Science」「跟 HRES 比」,正是要防的失敗。)
- **查不到 ≠ 造假,也 ≠ 真實**:一律標「不可查證」,並讓 G 反映「無法核對」的風險,而非反過來假設它是假的。
- **不要誤殺誠實貼文**:有可查證連結 + 主動講限制 + 語氣平實 + 無 CTA → A/D/E/G 應給低分;查證後落差小 → B 低分。**熱情 ≠ 營銷號**,落差與隱瞞才是。
- **分數要可複現**:固定這 7 維、各維附證據;同一篇貼文重跑分數應接近。
- **取文殘缺就停**:寧可請使用者重貼,不要對殘缺內容硬打分。
